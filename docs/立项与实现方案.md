# 坦克对战：钢铁代差 · 首版立项与实现方案

- 日期：2026-11-27
- 状态：首版代码已实现并通过自动化验收，正式部署待确认
- 产品全名：坦克对战：钢铁代差
- 短名：坦克对战
- App ID：`tank`
- 最终路径：`https://daobox.net.cn/tank/`

## 一、产品目标

把「坦克对战：钢铁代差」做成与斗地主同等级的 DaoBox 正式娱乐子程序。首版用有限内容验证核心循环，而不是做成失去平台能力的静态 Demo。

首版必须同时成立三件事：

1. 坦克对战本身可玩：操控、炮塔、装甲、固定炮台射界、掩体和残骸构成完整单局。
2. DaoBox 平台能力完整：游客、注册/登录、共享时长、会员、儿童游戏池、账号胶囊、打卡、反馈和云同步。
3. 可长期迭代：纯静态、零构建、数据与渲染解耦，后续能扩玩法、地图和坦克而不重写底座。

## 二、首版范围

### 包含

- 横屏优先的一张草地战场。
- 玩家固定驾驶中方 99A。
- 敌方固定使用虎式，单局 10 座固定炮台。
- PC 键鼠与手机双摇杆。
- 独立炮塔，按有限角速度跟随瞄准。
- 前/侧/后装甲差异与命中反馈。
- 可摧毁障碍、不可摧毁硬掩体、残骸动态掩体。
- 敌方车体完全固定，只保留炮塔限速追踪、视线、射程与射击。
- HUD、暂停、胜负结算、最佳战绩。
- PWA 安装、离线、版本刷新。
- `/api/backup?app=tank` 跨设备云同步与离线补传。

### 不包含

- 多地图、多阵营、多可玩坦克。
- 联网对战或排行榜。
- 金币、抽奖、单独付费内容。
- 正式部署、首页入口、Caddy 与 DNS 变更。

## 三、开源参考调研

### 1. niccolofanton/tanks-game

来源：`https://github.com/niccolofanton/tanks-game`

吸收点：

- 车体使用速度、角速度与阻尼形成坦克惯性，而不是普通角色平移。
- 坦克、子弹与障碍碰撞依赖手写几何，不引入物理引擎。
- 子弹需要独立生命周期与路径判定。
- 全窗口 Canvas 与固定主循环适合零构建 Web 游戏。

未采用：

- 本地双人键盘玩法。
- 子弹多次反弹。
- 类视野阴影系统。

### 2. vimaltiwari2612/classic-tank-1985

来源：`https://github.com/vimaltiwari2612/classic-tank-1985`

吸收点：

- 单文件也能形成完整游戏循环，说明首版可把资源规模压到很低。
- 障碍分为“可破坏砖墙”和“不可破坏钢墙”，会直接改变路线和炮线。
- 基础敌车实现至少需要视线、射击冷却和炮塔追踪；本项目只吸收前三项中的火力逻辑。
- 子弹命中地图格后销毁掩体，是形成动态战场的最低成本方式。

未采用：

- 随机乱走式敌人 AI；本项目明确采用完全固定的车体，只让炮塔按限速转动。
- 像素复古视觉；本项目采用原创俯视矢量轮廓。

### 3. quarkdev/battletanks

来源：`https://github.com/quarkdev/battletanks`

吸收点：

- 车体、炮塔、后座力、爆炸和装甲升级应拆成独立表现层。
- “装甲”不应只是一条总血量，应成为玩家可感知的战术差异。
- 命中、爆炸、炮口焰和屏幕反馈必须分层触发。

未采用：

- 多人 WebSocket 架构。
- 大量外部位图素材和物品系统。

## 四、核心玩法设计

### 4.1 战斗循环

1. 从主菜单进入战场。
2. 玩家在草地战场寻找射击角度。
3. 观察固定炮台射界，用车体正面承受火力并绕到侧后。
4. 炮弹摧毁木制/沙袋掩体，击毁坦克后留下残骸。
5. 清空 10 辆虎式获胜；玩家先被击毁则失败。
6. 结算展示击毁数、命中率、最高连击与用时，更新本机/云端最佳战绩。

### 4.2 操控

PC：

- `W/S`：前进、倒车。
- `A/D`：车体转向。
- 鼠标：炮塔目标方向。
- 鼠标左键 / `Space`：开火。
- `R`：手动装填。
- `Esc`：暂停。

手机：

- 左半屏虚拟摇杆：纵向控制油门，横向控制车体转向。
- 右半屏虚拟摇杆：炮塔目标方向；超过死区时持续开火。
- 双指可同时操作。

### 4.3 炮塔与车体

- 车体朝向与炮塔朝向分离。
- 炮塔最大角速度低于玩家快速甩鼠速度，不能瞬间对准。
- 移动中炮塔仍能转动，但车体急转会让射击窗口更难把握。
- 敌方车体在生成后完全固定，位置和朝向不再变化；炮塔仍可 360° 限速追踪。
- HUD 显示装填与炮塔偏角提示。

### 4.4 装甲代差

以弹道入射方向与目标车体朝向夹角判定：

- 正面扇区：伤害 ×0.65。
- 侧面扇区：伤害 ×1.00。
- 后部扇区：伤害 ×1.45。
- 极斜正面命中有小概率跳弹；跳弹不扣血，但产生独立音效和提示。

该规则同时作用于玩家和敌军，确保“代差”是双向规则，而非玩家隐藏加成。

### 4.5 障碍与残骸

- 木障：低血量可摧毁，阻挡炮线与移动。
- 沙袋：中血量可摧毁。
- 混凝土：不可摧毁，永久硬掩体。
- 坦克残骸：车体死亡后生成，继续阻挡移动和炮线，可作为动态掩体。

障碍被摧毁后立即从碰撞和视线判定中移除；残骸在单局内保留。

## 五、技术架构

```text
public/
├── index.html
├── style.css
├── data.js          # 坦克、障碍、地图与平衡参数
├── sync.js          # 本机/云端合并、节流与离线补传
├── game.js          # 输入、玩家物理、固定炮台、战斗与 Canvas 渲染
├── service-worker.js
├── manifest.json
└── icons/
```

### 5.1 渲染

- Canvas 逻辑坐标与 CSS 响应式尺寸分离。
- 世界坐标大于视口，相机平滑跟随玩家。
- 仅使用 Canvas 2D 矢量绘制，无外部图片依赖。
- 首版草地用确定性纹理与路径绘制，避免每帧重新随机。

### 5.2 碰撞

- 坦克移动采用圆形近似 + 分轴回退，降低旋转卡墙。
- 炮弹采用“上一帧到当前帧线段”与坦克/障碍做相交，防高速穿透。
- 炮弹命中坦克时用车体朝向计算装甲扇区。
- 视线检测用线段与障碍矩形求交。

### 5.3 敌方固定炮台

- 敌车在生成时确定 `x`、`y` 和车体 `angle`，存活期间永不改变。
- 炮塔以有限角速度追踪玩家，允许完整 360° 转动。
- 只有玩家进入射程且炮塔与目标之间无遮挡时才可开火。
- 装填、弹匣、炮塔转向和命中反馈正常运作；敌军不产生履带痕迹。
- 敌车被击毁后生成残骸，继续阻挡移动和炮线，成为动态掩体。

## 六、DaoBox 平台接入

| 能力 | 接入方式 |
|---|---|
| 游客身份 | portal Cookie + 浏览器本机存档 |
| 注册 / 登录 | `DB_HOME` 登录页，`src=tank` |
| 共享时长 | portal `/api/time` 与 `daobox:timeexceeded` |
| 会员不限时 | 由 portal 返回 `unlimited`，游戏不自行判断 |
| 儿童游戏池 | App ID 非学习类，由 worker 自动归入游戏池 |
| 账号胶囊 | 顶栏 `#db-account-slot` + portal `PILL_ANCHORS.tank` |
| 打卡 | portal `CHECKIN_APPS.tank` |
| 反馈 | portal 自动注入通用反馈入口 |
| 云同步 | 本应用直连 `/api/backup?app=tank` |

跨项目只做两个增量登记：

- `daobox-home/public/portal.js` 的 `PILL_ANCHORS` 增加 `tank`。
- `daobox-home/public/portal.js` 的 `CHECKIN_APPS` 增加 `tank`。

## 七、云同步协议

本机键：`dbtank-save-v1`

云端：`POST /api/backup`、`GET /api/backup?app=tank`

同步对象：

```json
{
  "version": 1,
  "updatedAt": 0,
  "stats": {
    "bestScore": 0,
    "bestKills": 0,
    "bestCombo": 0,
    "wins": 0,
    "battles": 0,
    "totalKills": 0
  },
  "settings": {
    "muted": false
  }
}
```

合并规则：

- 数值字段取最大值，累计字段取最大值，避免离线双设备重复叠加。
- 设置取 `updatedAt` 较新的有效档。
- 空档通过 `hasProgress()` 判定，不凭 JSON 是否存在。
- 云端为空：仅当本地有有效进度时才上传。
- 云端有效：无论本地是否为空，先合并后再决定上传。
- 本地为空且云端有效：只恢复，不上传覆盖。
- 任何网络失败写入待同步标记；恢复在线、回到前台或下次开战时补传。

同步节流：

- 战斗结束立即保存。
- 页面隐藏时保存。
- 60 秒内的重复写云合并为一次。

## 八、PWA 与路径

- `manifest.start_url = "./"`
- `manifest.scope = "./"`
- 部署到 `/tank/` 后，SW 默认 scope 即 `/tank/`
- `CACHE_VERSION = "dbtank-static-v1"`
- activate 时只删除：

```js
key.startsWith("dbtank-") && key !== CACHE_VERSION
```

- 导航请求网络优先，离线回退缓存。
- 静态资源缓存优先，后台更新。
- 跨域 portal.js 与 API 请求不进 SW 缓存。

## 九、验收标准

### 功能

- 能完成一局 10 敌遭遇战。
- 正面/侧面/后部命中产生不同伤害与提示。
- 炮塔不能瞬间转向。
- 木障和沙袋可摧毁，残骸生成并形成掩体。
- PC 与手机双摇杆均可完成移动、瞄准、装填和开火。
- 暂停、重开、结算、版本刷新可用。

### 平台

- 登录用户顶栏显示账号胶囊与打卡 chip。
- 时长耗尽时弹出锁定界面。
- 儿童身份显示儿童胶囊，使用游戏池。
- 云档可在第二个浏览器上下文恢复。
- 本地空档不会覆盖有效云档。
- 离线完成战斗，恢复网络后补传。

### PWA

- 断网可打开已缓存页面。
- SW 新版本激活不删除非 `dbtank-*` 缓存。
- portal.js 或账号接口异常时，游戏仍可启动。

## 十、部署边界

本阶段不执行：

- 不部署阿里云。
- 不改 Caddy。
- 不改 DNS。
- 不改首页入口。
- 不发布正式 URL。

代码提交与推送可执行；部署条件与静态目录映射需用户后续确认。
